# 主题发布台（Theme Release Station）

品牌团队的主题发布前检查工具：在改动主色、文字色或按钮状态色之前，先在依赖图上看清影响面，
提前发现哪些页面会失去对比度或继承到错误的颜色。

技术栈：**React 18 + TypeScript + Vite**，数据只保存在浏览器 `localStorage`，无任何后端依赖。

## 运行方式

```bash
npm install        # 安装依赖
npm run dev        # 开发服务器（默认 http://localhost:5173）
npm test           # 运行全部测试（Vitest，49 个用例）
npm run build      # 类型检查 + 生产构建（输出到 dist/）
npm run preview    # 本地预览生产构建产物
```

## 界面布局

```
┌────────────────────────────────────────────────────────────────┐
│ 顶栏：示例切换（默认主题 / 高对比·问题场景）· 恢复示例 · 撤销/重做 │
├──────────────┬──────────────────────────────┬──────────────────┤
│ 左：令牌依赖  │ 中：组件预览                  │ 右：诊断          │
│ 基础令牌列表  │ 导航/排版/按钮/徽章/提示/卡片 │ 循环依赖          │
│ 语义令牌列表  │ /表单（浅色/深色/上下对比）   │ 缺失引用          │
│ 来源链·被引用 │ 默认/悬停/按下/禁用四种状态   │ 对比度逐项结果    │
└──────────────┴──────────────────────────────┴──────────────────┘
```

- **左侧 · 令牌依赖**：基础令牌（跨主题共享的色板）与语义令牌（按浅/深主题定义）及其引用关系。
  点击令牌可查看**来源链**（语义颜色一路追溯到哪个基础令牌、最终色值是多少）和**被引用于**
  （改动它会波及哪些语义令牌，含间接层数）。
- **中间 · 组件预览**：一组真实组件（导航、标题/正文/链接、按钮、徽章、错误/成功提示、卡片、表单），
  可同时显示浅色 + 深色；按钮渲染默认/悬停/按下/禁用四种状态（悬停态也可真实交互）。
- **右侧 · 诊断**：循环依赖、缺失引用、对比度检查。每条对比度结果都渲染**实际文本、实际背景、
  实际字号/字重**，并给出比值与 WCAG 等级（AAA / AA / AA大字号 / 不达标；禁用态按 WCAG 豁免标注）。

## 令牌模型与依赖图

```
基础令牌（base）          语义令牌（semantic，按主题）         组件
blue.600 = #2563eb  ◄──  color.accent.default (浅)      ◄── 主要按钮背景
blue.400 = #60a5fa  ◄──  color.accent.default (深)      ◄── 主要按钮背景
blue.700 = #1d4ed8  ◄──  color.accent.hover  (浅)       ◄── 主要按钮悬停
blue.50  = #eff6ff  ◄──  color.accent.subtle ◄── color.badge.bg ◄── 徽章背景
```

- 基础令牌直接持有颜色；语义令牌的值是**引用**（指向基础令牌或同主题的另一个语义令牌）
  或**直接颜色**（覆盖用）。
- 修改一个基础令牌，解析结果沿引用链传播到所有依赖它的语义令牌、两个主题与 hover/disabled
  状态色，预览与诊断即时更新。
- **预览无法绕过依赖图**：`src/preview.css` 中的颜色只允许写 `var(--t-*)`，变量由
  `PreviewPanel` 根据解析结果统一注入，没有任何散落的硬编码色值（应用外壳自身的 UI 样式
  与被检查的主题令牌无关，见 `src/styles.css`）。
- **循环拒绝**：编辑器提交前由 `wouldCreateCycle` 预检，会成环的修改被拒绝并提示环路径；
  解析器本身对循环安全（返回错误而非死循环），诊断面板会列出数据里已存在的环
  （问题场景示例中就内置了一个）。
- 对比度按 WCAG 2.x 计算相对亮度与比值；大字号阈值为 ≥24px 或 ≥18.66px 且粗体。

## 内置示例

| 示例 | 说明 |
| --- | --- |
| 默认主题 | 健康基线：浅/深两个主题下全部非豁免检查对都达到 AA |
| 高对比 · 问题场景 | 故意改错的语义映射：黄色主色配白字、过浅的次级文字、引用不存在的 `neutral.450`、徽章两个令牌互相引用成环 |

“恢复示例”会放弃当前修改、回到示例初始状态；加载示例与恢复都可撤销。
所有编辑自动持久化到 `localStorage`（键：`theme-release-station:v1`），刷新后恢复。

## 操作

- 点击令牌行的 **✎** 编辑：基础令牌改颜色（弹窗会显示影响面：波及多少语义令牌与对比度检查）；
  语义令牌可改引用目标或直接颜色。
- 快捷键：`Ctrl/⌘+Z` 撤销，`Ctrl/⌘+Shift+Z` 重做（历史上限 100 步）。
- 诊断面板可按主题过滤、只看未达标；点击任意令牌名跳转到左侧的来源链视图。

## 目录结构

```
src/
  core/
    tokens.ts      令牌模型、解析、循环/缺失检测、反向依赖（被引用于）
    contrast.ts    十六进制归一化、WCAG 亮度/比值/等级
    pairs.ts       对比度检查对注册表（哪段文字在哪类背景上、字号字重）
    examples.ts    内置示例：默认主题 + 高对比问题场景
    store.ts       applyEdit（唯一修改入口，含校验）+ 撤销/重做历史 + localStorage
  components/
    TokenPanel.tsx        左侧：令牌列表、来源链、被引用于
    PreviewPanel.tsx      中间：把解析结果注入 CSS 变量并渲染组件
    DiagnosticsPanel.tsx  右侧：循环/缺失/对比度诊断
    TokenEditor.tsx       编辑弹窗（影响面提示、循环拒绝提示）
  preview.css      预览组件样式（颜色只允许 var(--t-*)）
  styles.css       应用外壳样式（与主题令牌无关）
```

## 测试

`npm test` 运行 49 个用例，覆盖需求要求的核心行为：

- **依赖传播**（`tokens.test.ts`）：改基础令牌后直接与间接依赖的解析结果同步更新；
  `getDependents` 的正确性（含深度）。
- **循环拒绝**（`tokens.test.ts` / `store.test.ts` / `App.test.tsx`）：解析器对循环安全、
  `wouldCreateCycle` 预检、`applyEdit` 拒绝成环修改且文档不变、UI 弹窗展示拒绝原因。
- **主题覆盖**：同一语义令牌在浅/深主题独立解析，改一个主题不影响另一个。
- **状态色**（`store.test.ts`）：hover 等状态令牌随基础令牌更新，并反映到对比度评估。
- **撤销/重做**（`store.test.ts` / `App.test.tsx`）：编辑可撤销重做、新编辑清空重做栈、
  被拒绝的编辑不进历史、加载示例也可撤销、历史上限。
- **对比度**（`contrast.test.ts`）：归一化、已知参考值（黑白 21:1）、等级阈值与大字号判定。
- **内置示例**（`examples.test.ts`）：默认主题零问题；问题场景必含循环、缺失与多处不达标。
- **UI 冒烟**（`App.test.tsx`）：三栏渲染、示例切换、编辑传播到 CSS 变量、localStorage 持久化。
